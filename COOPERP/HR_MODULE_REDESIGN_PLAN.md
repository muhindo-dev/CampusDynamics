# HR Module Redesign Plan (eadmin)

Prepared 6 October 2026 by MIS. Scope: the 23 HR screens in eadmin, their exports and their printed
documents. Status of each item is tracked in section 6.

## 1. What the audit found

Three independent audits read every HR screen, its code-behind, exports and print output.

| Area | Finding |
|---|---|
| Visual consistency | 277 distinct colours across the module (the design system defines about 10). Six private CSS dialects (`hr-`, `ct-`, `cr-`, `lv-`, `lf-`, `pr-`, `ps-`, `hrc-`, `pa-`), seven page-title sizes, gradients on six pages, 20px pill badges, hover lifts, shadows and animations. No screen uses the design-system page header. |
| Wording | About 240 em dashes, decorative glyphs used as icons (tick, cross, envelope, flag, arrows), explanatory boxes on every modal, chatty lines ("all caught up!", "Everything is in order", "Ready to sign off?"), raw status codes and exception text shown to users. |
| Navigation | No way to move between pages of the same area except the sidebar; inconsistent back links; HR Leave Management and HR Settings have no page header at all. |
| Exports | Only three exports in the module, all CSV, in different formats: no letterhead, internal IDs, ISO dates, no units, no totals, no UTF-8 BOM on one of them. No payroll register, bank schedule, statutory schedules, contract register or leave export. |
| Printed documents | Four different letterheads, one with an invented address and motto; Times New Roman on two, sans-serif on others; cursive "Brush Script" e-signatures on the renewal pack; the payslip misspells the university name ("Mutesa"); session report repeats the same four numbers in five charts. |
| Security | HREmployees exported the staff list with pay data and ran password resets without sign-in; HRAllowances and HRDeductions employee search returned staff names without sign-in. **Fixed on 6 Oct (commit 394da96).** |
| Data and logic bugs | See section 4. The most serious are in payroll. |

## 2. The HR standard (applies to every screen)

### 2.1 Building blocks (shared, do not copy into pages)

| File | Purpose |
|---|---|
| `COOPERP/NewScreens/css/hr.css` | All HR screen styling, prefix `hr-`. Pages keep only page-specific layout rules that use the same tokens. |
| `App_Code/HumanResource/HrAccess.cs` | `HrAccess.RequireHr(json)` at the top of every `?ajax=` / `?action=` handler and every HR page load; one access rule (admin, `hr_manager`, legacy HR roles). |
| `App_Code/HumanResource/HrExport.cs` | Every export. `.xlsx`: letterhead rows (university, office, title, filters, generated by/at), navy header, banded rows, UGX `#,##0`, dates `dd mmm yyyy`, totals row, frozen and filterable header, landscape A4 with page numbers. `.csv`: same columns, UTF-8 BOM, ISO dates, plain numbers. File name `MRU-HR-{report}-{yyyyMMdd-HHmm}.{ext}`. |
| `App_Code/HumanResource/HrDocument.cs` | Every printed document: crest letterhead, document title, reference grid, plain section headings, ruled tables with totals, signature blocks, footer with print time. Sans-serif, A4. |

### 2.2 Page layout

1. Navy page header (`hr-header`): icon, title, one-line subtitle (at most 8 words), up to three actions on the right.
2. Area tabs (`hr-tabs`) directly under the header, identical on every page of the area:
   - **People:** Overview | Employees | Contracts | Renewals | Leave applications | Leave balances | Profile requests
   - **Payroll:** Payroll runs | Payslips | Allowances | Deductions
   - **Settings:** Organisation and pay scales | Payroll and tax settings
   - **Appraisal:** Overview | Sessions | Appraisals | Reports | Competencies | Expected standards
3. At most one KPI row (four to six tiles), neutral colours; a tile is a link when it filters the list below.
4. Filter bar, then the main card with the table; bulk bar appears only when rows are selected.
5. Detail views use definition lists (`hr-dl`) and cards; workflow position uses `hr-stages`.

### 2.3 Visual rules

- Colours: navy `#05275C`, accent `#174DA4`, surface `#f5f7fa`, border `#e0e5ed`, text `#1a1a2e`, grey text.
  Status colours (green, amber, red, blue) only inside status badges and for a single alert value.
- Five badge kinds only: neutral, info, ok, warn, bad. Square, uppercase, 10px.
- Radius 0 on inputs, buttons and badges; 2px modals; 4px cards. No gradients, no hover lift, no
  animation beyond a plain show/hide, no drop shadows except the toast.
- Icons: inline Feather-style SVG. No emoji, no character glyphs used as icons.
- Money right-aligned in normal text colour; the unit (UGX) in the column header, not in each cell.
- Empty values: blank, or "Not recorded" where the absence matters. Never a dash character.

### 2.4 Wording rules

- Sentence case for labels, buttons, headings ("Payroll runs", "Add allowance").
- No em or en dashes. Use a colon in headings ("Section B: Achievements"), "to" for ranges
  ("1 Oct 2026 to 31 Dec 2026"), and a comma or full stop in sentences.
- No exclamation marks, no "Note:" boxes, no explanations of how the system works. A hint is one
  short line under the field, only when the field is not self-explanatory.
- One name per thing across the module: Supervisor (not reviewer or appraiser in staff-facing text),
  Awaiting HR (not Completed or Finalized), Head of Department, Payroll run, Payslip, Contract renewal.
- Statuses shown as words, never as codes (`SUPERVISOR_IN_PROGRESS` becomes "With supervisor").
- Errors: a plain sentence of what to do; never raw exception text.
- Dates on screen: `6 Oct 2026`; with time: `6 Oct 2026, 14:05`.

## 3. Target structure per screen

**People**
- *Overview (HRDashboard):* four KPIs (Active staff, Contracts ending in 90 days, Renewals with HR, Leave awaiting action); one "Needs action" list; one "Contracts ending soon" table. No quick-link tiles, no duplicated alerts.
- *Employees:* KPIs that filter (All, Active, No valid contract, Duplicate records); directory table; profile panel with four tabs (Details, Contracts, Leave, Payroll); one "Reset login" action replacing Change Password / Reset Access / Fix Login; staff register export.
- *Contracts:* KPIs that add up to the total (Valid, Ending in 90 days, Ended, No contract); one consistent "ending" definition (90 days); one bulk "Set status"; the Renew modal links to Contract renewals; contract register export.
- *Renewals:* four KPIs (No application, With HR, At Council, Issued); tabs unchanged; one-line hints instead of info boxes; Council schedule export with the same columns as the print.
- *Renewal view:* header, action bar, content cards; appraisal summary inside the applicant card; no mechanics explanations; plain email.
- *Renewal print:* HrDocument letterhead; typed e-signature lines (name, date, time) instead of cursive; Yes/No instead of coloured ticks; Council approval line.
- *Leave applications:* server-side filters and search kept by the pager; working status tiles; neutral initials; status badges from the five kinds; export.
- *Leave form:* section titles "Section 2: Head of Department"; numbers, not glyphs; one-line policy; print shows all four sections with signature lines for HOD, HR and Vice Chancellor.
- *Leave balances (HRLeaveManagement):* page header; Aqua or plain tables; searchable employee picker without postback in the modal; export.

**Payroll**
- *Payroll runs:* four KPIs (Runs, Gross, Net, Awaiting approval); runs table with one actions menu; run detail with summary strip and read-only register with totals; exports (register, bank schedule, statutory schedules).
- *Payslips:* review queue filtered by run; batch approve and reject with a shared reason; locked runs read-only; rejection reason visible; payslip print as a proper financial document (letterhead, employee and bank details, earnings and deductions side by side, net pay in words, employer contributions).
- *Allowances, Deductions:* one shared layout; employee filter that survives postback; types from the settings tables; export of a period's items.

**Settings**
- *Organisation and pay scales (HRSettings):* page header; tables with add and edit dialogs; employee picker for head of department; deactivate instead of delete for referenced rows.
- *Payroll and tax settings (HRConfig):* plain PAYE band table; short factual labels; legal claims removed from hints; Reset to defaults requires typing the confirmation and is recorded.

**Appraisal**
- *Overview (AppraisalDashboard):* four KPIs (Total, Not started, With supervisor, Awaiting HR), one HR queue table, one overdue list. Analysis moves to Reports.
- *Sessions:* list, create and edit; session detail shows session information and actions only; a link to the session's appraisals; dialogs instead of browser alert/prompt.
- *Appraisals (AppraisalView):* list, filters, batch actions and HR review, restyled; section headings identical to the printed form.
- *Reports:* the single analysis page: completion by category, department and session; one classification table; appraisal records export; session report link.
- *Session report:* HrDocument; session details, one summary table, category breakdown, roster, outstanding items, sign-off with blank dates.
- *Appraisal form print:* HrDocument; one HR signature block; one date format; table headers light, not solid blue.
- *Competencies, Expected standards:* same layout, linked to each other, printable catalogue.

## 5. Decisions needed (not changed until confirmed)

1. **Payroll tax basis (Finance / URA to confirm).** PAYE is computed on gross minus employee NSSF; NSSF on basic pay; Local service tax as a percentage of basic (Uganda LST is a fixed banded amount); Kabaka contribution charged to every employee although the setting describes it as for some staff. The redesign keeps the current calculations unchanged until Finance confirms the rules.
2. **Leave balances.** Granted leave applications do not update leave balances, and the Vice Chancellor types the accumulated days by hand. Proposal: on grant, record the days in leave taken and compute the balance. Needs HR's confirmation of the entitlement rules.
3. **Settings stored but unused** (employer NSSF, overtime multiplier, gratuity, working days, financial year start). Proposal: hide them until payroll uses them.
4. **Letterhead details.** The print letterhead shows the crest, university name and office. Add the postal address and telephone once HR confirms the official ones (the codebase contains three different P.O. boxes).

### Additional defects found and fixed during the work
- Payroll: approve and lock wrote text into an integer column and always failed.
- Contracts: creating or editing a contract with fixed amount 0 failed under strict mode; "Contract" and "Temporary" types were offered but rejected by the database.
- Employees: the directory showed only the first 50 staff (no paging); editing a Support or Consultant employee changed them to Administrative.
- Appraisal: lists now include four session-4 records whose staff record no longer exists ("Staff record not found").

### Visibility rule: only what has reached HR
HR lists, detail pages, prints and exports show a record only once it has reached HR. Earlier stages
appear as counts in the stat tiles only.
- Appraisals: Completed and HR reviewed (Cancelled through its own filter).
- Renewals: Awaiting HR and later (Forwarded, Approved, Not approved, Deferred, Contract issued).
- Leave: HOD approved and later, plus the user's own applications and those they approve as HOD.
